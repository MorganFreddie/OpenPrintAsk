## 一、为什么「打不好」搜不到答案

3D 打印新手最常说的一句话是「打不好」。

这三个字里可能藏着完全不同的故障：

- 首层不沾，打印继续走，变成「炒面」；
- 喷嘴堵了，料挤不出来，但机器还在动；
- 多色换料时堵，单色不堵；
- 平台脏了，热床 60℃ 也没用；
- 室温 30℃，前 20 分钟正常，后面热蠕变。

直接把这句抱怨丢进搜索引擎，会得到一坨「看起来相关」的页面；直接丢给大模型，会得到一段「听起来合理」但没有出处的建议。

问题不在搜索，也不在模型，而在**问题没有被编译**。

我在 6 月做「得师傅」时就注意到：厂商的打印义诊大多停留在「按图找病症 → 官方 wiki」，社区经验帖很多，但没有人把「用户的原话」翻译成「可检索的任务书」。拓竹后来的打印义诊改善了这一点，但仍然是基础的、以官方内容为主的。其他厂商更少。

所以我想做一个很小的 sidecar：**不替换私域知识库，只在私域不够用的那一刻，先判断缺什么，再决定搜什么。**

## 二、三条真实病例

下面三条不是编的，是一位真实用户（也就是我）在拓竹 A1 上遇到的：

### 病例 1：单色堵料

```text
品牌：拓竹
机器：A1
材料：PLA、PETG
是否官方材料：否，使用创想三维、爱丽兹
常用耗材：PETG
现象：打印龟壳模型时会产生喷头堵料
已尝试：停止打印，退料，关机
环境：室内 30 度
解决方法：开机，撞针疏通喷头，加热喷头 230 度再进料
```

### 病例 2：多色堵料

```text
品牌：拓竹
机器：A1
多色实现形式：AMS Lite
材料：PLA、PETG
是否官方材料：否
现象：打印多色模型时会产生喷头堵料，单色不堵
已尝试：停止打印，退料，关机
环境：室内 28 度
解决方法：撞针疏通；拆喷嘴后用加热铁棒通喷嘴内部；加热喷头 230 度再进料
```

### 病例 3：首层不沾，变成炒面

```text
品牌：拓竹
机器：A1
材料：PLA、PETG
现象：打印小船模型时底部不在热床，打印仍在继续，产生炒面
已尝试：停止打印
环境：室内 28 度
解决方法：取床板，温水和洗洁精清洗正反面，沥干/擦干，热床烘干后再打
```

这三条病例有一个共同点：**用户的「解决方法」写得很具体，但「已尝试」写得很短。** 如果系统把「解决方法」误当成「已尝试」，就会漏掉最该建议的那一步。这个问题我在实现里专门处理了：先切掉「解决方法/已解决/修复方法」之后的内容，再解析「已尝试」。

另一个共同点是：**多色病例必须写「单色是否也堵」。** 这句话决定系统先查「喷嘴本身」还是「换料残留/冲刷不足」。

## 三、系统怎么做

```text
一句抱怨
  → 槽位：机型 / 材料 / 现象 / 已尝试 / 环境 / 意图
  → 缺口：私域覆盖了什么、还缺什么、哪个缺口需要问用户
  → 任务书：每条 query 带 Mode / Site / Cnt / Freshness / Industry + purpose + covers
  → 证据：去重、排序、抽数值、找冲突、算覆盖率
  → 回答：结论 + 步骤 + S 编号 + 分歧 + 追问
```

### 3.1 先缺口，后检索

没有缺口的搜索是碰运气。比如「A1 堵料」至少有三种可能：喷嘴堵、挤出机打滑、热蠕变。系统会先判断：

- 材料写了吗？没写，先问；
- 是吸湿材料吗？是，才问烘干；
- 多色吗？是，才查 AMS Lite 的切料口、缓冲、废料塔；
- 室温 30℃ 吗？是，才把热蠕变放进排查顺序。

每条 query 都带 `purpose` 和 `covers`，回答里能回看「这条搜索是为了补哪个缺口」。

### 3.2 私域旧笔记不静默平均

私域笔记里有一条旧记录写着「PLA 热床 50–60℃」，但用户当前是 60℃、空调直吹、PEI 板。系统不会把旧笔记和公开资料平均成「55℃」，而是把冲突显式列出来：

> 热床温度说法不一致：官方 60℃；官方 50℃；其他来源 60℃；其他来源 50–60℃。建议先采用 60℃ 这一侧，并记录复测结果。

这条「分歧卡」比一个漂亮的单点答案更有用，因为它告诉用户：**这里真的有争议，你需要自己复测。**

### 3.3 证据带 S 编号，回答能回查

每条公开证据有 `S1..Sn`，回答的每一步都挂编号。点 S 编号可以跳到「依据」页，看到标题、站点、日期、相关度、层级（官方/社区/通用）。

这不是为了好看，是为了让「这句话从哪来」可审计。比赛要求「模型智答与产品问答」，我理解的重点不是模型多会写，而是**回答能不能被验证**。

### 3.4 认可度：用「复现回执」，不用点赞

社区答案的排序，通常靠点赞、收藏、置顶。但 3D 打印的「有效」是有条件的：

- 同机型吗？
- 同材料吗？
- 同现象吗？
- 同一步骤吗？
- 是最近的吗？

所以我没有做「全站热榜」，也没有做「人工置顶」。我做的是一个很小的回执：

- 用户对某一步点「有效 / 没解决 / 还没试」；
- 回执绑定机型 + 材料 + 现象 + 步骤 + 日期；
- 90 天半衰，超过 180 天不参与排序；
- 少于 3 条不显示汇总；
- 排序硬顺序是「安全/官方 > 机型与固件匹配/新鲜度 > 回执」，回执最多 +15%，不能翻官方；
- 来源存快照，404 或早于机型发布，标「可能失效/不适用」并降权。

这样做的代价是冷启动很慢：前几条回执几乎不显示。但我觉得这比「高赞但过时」更接近打印义诊真正需要的东西。

## 四、live 实测

2026-11-11，用元宝搜索 SearchPro 的 `lite` 版本跑多色堵料：

- 5 条查询，全部 live；
- 总耗时 1527ms；
- 10 条证据：官方 10、社区 0、通用 0；
- 0 处冲突；
- 5 个 RequestId 均非空；
- 置信度 `medium`，覆盖率 `covered=4, insufficient=1`。

回答的第一版是「先按证据排序，再动手」，步骤是「堵头」「如何有效防止喷嘴堵塞」「3D打印堵头排查清单」，S1–S3 全是 wiki/官方文档。它没有答到 AMS Lite 的冲刷量和废料塔，`uncertainties` 里明确写了：

> 有 1 个缺口没有足够公开证据：A1 的 AMS / 多色换料，冲刷量、废料塔和换料温度怎么设？

这就是我想要的行为：**不知道就说不知道，把缺口变成追问，而不是硬编一个「冲刷 200mm」的参数。**

后来我补了一个堵料回答器，把步骤改成「先停打退料 → 加热判断堵在哪 → 通针/冷拉 → 多色查 AMS Lite / 单色查热蠕变 → 空挤复测」。单色堵料到了 `high`，多色仍是 `medium`，因为公开证据确实没覆盖 AMS 的细节。

## 五、v2 做了什么

- **界面 V2**：左栏只负责「把问题写清楚」，右栏默认给师傅诊断，依据/任务书/轨迹降为二级 tab；正文 15px，去术语。
- **词表外置**：`data/lexicon.json`，品牌、机型、材料、现象、环境、地区、已尝试、耗材品牌都可改；改完跑测试，不用改代码。
- **输入手册**：`docs/input-guide.md`，把「怎么填五个格子」写成可照着做的模板。
- **7 个演示案例**：新增 A1 单色堵料、A1 + AMS Lite 多色堵料、A1 首层炒面。
- **20 条私域笔记**：补了堵料三分法、夏季热蠕变、AMS Lite 耗材头、PLA/PETG 混用界面、热床单变量、挡风等。
- **`/api/compile`**：输入时实时看编译器读到了什么，不用先跑完整搜索。
- **回执 MVP**：`/api/receipts`，按机型/材料/现象/步骤聚合；不足 3 条不显示。
- **live / replay 双模式**：有 key 走 live，没有 key 走 replay，界面明确标记，不把演示当线上。

## 六、限制与下一步

- 槽位和数值断言是规则 + 正则，不是通用 NLU；换域要重写词表。
- 只有 7 个案例、20 条笔记，不能宣称「命中率 90%」；live 也只跑了几条。
- 多色的 AMS 细节，公开证据不足；这部分只能靠用户回执和私域病例补。
- 单机单进程，没有鉴权、限流、多租户；不要直接暴露公网。
- 回执有冷启动问题；少于 3 条时界面只显示「暂不显示汇总」。

下一步我想做三件事：

1. 再收 20 条真实病例，把「单色/多色/首层/拉丝/树脂」补到可复测；
2. 让用户能直接改 `lexicon.json` 和病例，跑一条命令看红绿；
3. 把回执做成「同机型同材料」的小样本，而不是全站热榜。

## 七、怎么跑

```powershell
# 无 key 也能跑：auto 会落到 replay
Copy-Item .env.example .env
python server.py --mode replay --port 8765

# 有 SearchPro key：写进 .env 的 WSA_API_KEY
python server.py --mode live --port 8766
```

打开 <http://127.0.0.1:8766/>。
