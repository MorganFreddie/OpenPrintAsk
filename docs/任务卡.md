# 任务卡：五层参与方式

> 你不用先会写 Python。选一层，按验收标准交一件小事；每件都对应一个可检查的结果。

## 任务 1（数据层，30–60 分钟）：补 3 条真实病例

**做什么**

把最近遇到的 3 个问题，按 `data/cases.json` 的字段写成 JSON。必须包含：

- 机型（品牌 + 型号）
- 材料（种类，混用就写混用）
- 现象（什么时候、在哪、变成什么样）
- 已尝试（只写做过的）
- 环境（室温/气流/湿度/地区）
- 最后怎么解决的（如果有）

**验收**

```powershell
python -m unittest discover -s tests -v
```

计数测试从 7 变成 10，其他测试仍绿。

**你会学到**：为什么「已尝试」不能写解决方法；为什么多色要写「单色是否也堵」。

---

## 任务 2（测试层，20–30 分钟）：加一条会失败的测试

**做什么**

从真实用户的话里挑一句系统识别错的，写进 `tests/test_planner.py`：

```python
def test_my_sentence(self):
    p = plan("我的原话……")
    self.assertEqual(p["slots"]["model"], "A1")
```

先运行，确认它失败；再改 `data/lexicon.json` 或 `planner.py`，让它通过。

**验收**

```powershell
python -m unittest discover -s tests -v
```

新测试从红变绿，其他测试不红。

**你会学到**：规则系统不是「猜」，是「用失败样例把边界钉出来」。

---

## 任务 3（界面层，20 分钟）：改一句文案或一个颜色

**做什么**

改 `web/index.html` 或 `web/assets/style.css` 里一处：

- 把「开始诊断」改成你平时会说的词；
- 把主按钮橙色换成更接近品牌的颜色；
- 把某个提示改成更短的一句。

**验收**

刷新 <http://127.0.0.1:8766/>，截图前后对比；不要出现溢出的按钮或看不清的灰字。

**你会学到**：文案也是检索的一部分——用户看不懂「槽位」，就不会填。

---

## 任务 4（逻辑层，1–2 小时）：加一个口语说法

**做什么**

在 `data/lexicon.json` 的 `symptoms.clog.words` 里加一个你常说的词，比如「不出料」「挤不出来」。

然后加一条测试：

```python
def test_my_clog_word(self):
    p = plan("A1 打一半不出料")
    self.assertIn("clog", p["slots"]["symptom_ids"])
```

**验收**

测试绿；`/api/compile` 的 `chips` 里能看到「堵头 / 挤出不足」。

**你会学到**：词表外置的意义——改数据，不改代码。

---

## 任务 5（发布层，30 分钟）：做一次干净的提交

**做什么**

```powershell
git status --short
git diff
git add README.md data/lexicon.json tests/test_planner.py
git commit -m "feat: 补一条堵料口语说法"
```

确认 `.env`、`*.sqlite3`、`runs/*.json` 没有被加入。

**验收**

`git show --stat HEAD` 只包含你改的文件；commit message 能看懂。

**你会学到**：版本隔离、最小提交、可回滚。

---

## 建议顺序

1. 先做任务 1（有真实材料，最有成就感）
2. 再做任务 3（立刻能看到界面变化）
3. 然后任务 2 / 4（开始碰逻辑）
4. 最后任务 5（把成果交出去）

每完成一件，在 `docs/开发手册.md` 的「已知坑」里补一句你踩到的坑；这比写总结更有用。
