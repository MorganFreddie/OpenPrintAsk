# 开发手册（v2）

> 目标：让「改一个词、加一条病例、换一句文案」都能在 5 分钟内看到结果，而不是先读完整套代码。

## 1. 一分钟跑起来

```powershell
cd C:\Users\newland\Desktop\printer\deshifu-wsa-v2
python server.py --mode auto --port 8766
```

- 有 `WSA_API_KEY` 时走 live；没有时自动落 replay，界面会标出来。
- 打开 <http://127.0.0.1:8766/>。
- 只改前端：刷新即可；改 Python：重启 `server.py`。

## 2. 数据流

```text
web/index.html + app.js
  → POST /api/compile      只编译，不检索
  → POST /api/ask          编译 + SearchPro + 证据 + compose
      planner.py           槽位 / 缺口 / 查询任务书
      kb.py                私域笔记（FTS5）+ 回执
      wsa.py               SearchPro 客户端（Bearer / TC3 / replay / record）
      fuse.py              去重 / 排序 / 数值断言 / 冲突 / 覆盖率
      compose.py           按症状组装步骤与引用
      pipeline.py          编排 + trace
```

关键返回结构见 `README.md` 的「主要接口」，或直接看 `runs/*.json`。

## 3. 最常见的四种改动

### 3.1 加一个品牌/机型/材料/现象

改 `data/lexicon.json`，不要改 `planner.py` 里的常量：

```json
{
  "models": {
    "A1": {"brand": "拓竹", "site": "wiki.bambulab.com", "released": "2023-12"}
  },
  "materials": {"PETG": {"hygroscopic": true}},
  "symptoms": {"clog": {"label": "堵头 / 挤出不足", "words": ["堵料", "堵头"]}}
}
```

改完重启，跑：

```powershell
python -m unittest discover -s tests -v
```

如果新词没识别，先看 `/api/compile` 返回的 `slots.raw / parse_text`，确认它是不是被「解决方法」切掉了。

### 3.2 加一条真实病例

改 `data/cases.json`，字段：

```json
{
  "id": "a1-clog-single",
  "title": "A1 单色堵料",
  "question": "用户原话……",
  "why": "这条病例想验证什么",
  "expect": {"brand": "拓竹", "model": "A1", "symptom_ids": ["clog"]}
}
```

`cases.json` 目前 7 条；加完把 `tests/test_planner.py` 的计数改掉，或在测试里改成 `>= 7`。

### 3.3 加一条私域笔记

改 `data/kb_seed.json`，然后重新 seed：

```powershell
python -c "from kb import KnowledgeBase; KnowledgeBase().init().seed(); print('seeded')"
```

注意：`init()` 只在 `notes` 为空时自动 seed；已有库要显式 `seed()`。笔记是「病例/经验」，不要写成百科。

### 3.4 加一个回答分支

在 `compose.py` 写 `_your_symptom(ctx)`，返回：

```python
{
  "headline": "...",
  "summary": "...",
  "steps": [{"n": 1, "title": "...", "text": "...", "sids": ["S1"]}],
  "conflict_notes": [...],
  "followup": "...",
  "uncertainties": [...],
}
```

然后在 `builders` 里注册：

```python
builders = {"clog": _clog, "multi_color": _clog, "your_symptom": _your_symptom}
```

步骤里的 `sids` 用 `_sids(evidence, "关键词")`，不要手写不存在的 S 编号。

## 4. 回执怎么调

- 表：`receipts`，唯一键 `(client_id, run_id, step_title)`。
- 写入：`POST /api/receipts`，`outcome` 只允许 `fixed / not_fixed / not_tried`。
- 聚合：`GET /api/receipts?model=&material=&symptom=`，只看 180 天内、同机型/材料/现象；少于 3 条 `visible=false`。
- 前端键：`web/assets/app.js` 的 `receiptKey()` 用 `plan.slots.model / materials / symptom_ids`，不要用 `answer.symptom` 的中文标签。

## 5. 调试顺序

1. 先看 `/api/compile`：槽位对不对？缺口对不对？
2. 再看 `/api/ask` 的 `search.calls`：每条 query 的 `request_id / pages / error / fallback`。
3. 再看 `evidence`：`tier`、`relevance`、`date`、`covers`。
4. 最后看 `answer`：`coverage.insufficient` 和 `uncertainties` 是否如实。
5. 任何一次运行都能从 `/api/runs/{run_id}` 下载完整 trace。

## 6. 已知坑

- **BOM**：`.env` 带 BOM 时第一行 key 会读不到；用 `UTF8Encoding($false)` 写。
- **key 被注释吞掉**：如果 `WSA_API_KEY` 写在 `#` 同一行后面，`config.py` 读不到；key 单独一行。
- **SQLite 线程**：`KnowledgeBase` 每线程一个连接；测试里关连接再删临时目录，否则 Windows 会报 `WinError 32`。
- **端口**：v1 用 8765，v2 用 8766；不要同时起两个抢端口。
- **headless 截图**：当前 DSH 沙箱里 Chrome/Edge 会报 `crashpad OpenProcess` + `platform_channel`，用普通浏览器拍。
