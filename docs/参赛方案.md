# 参赛方案：把「会问」做成竞争力

> 赛事：CSDN 元宝搜索开发者征文大赛（让 AI 查得到，更信得过）
> 赛道：模型智答与产品问答（公网信息 + 私域知识混合问答）
> 阶段：可演示原型
> 当前日期：2026-11-09；截稿：2026-11-22 23:59:59
> 一句话策略：**不拼「我接入了」，拼「我会问」；不拼功能数量，拼证据纪律；不编线上指标，主动标注边界。**

---

## 1. 为什么选这个赛道

赛事有 4 个赛道：资讯追踪、调研分析、学习与创作、模型智答与产品问答。

前三个赛道都要求「持续、大量、时效性强」的内容生产，单人 13 天内很难做出差异化；第四个赛道明确写了「公网信息 + 私域知识」的混合问答，正好对应「得师傅」的私域笔记 + SearchPro 的公网证据。

更关键的是：**这个赛道允许「小场景打穿」**。我不需要覆盖所有 3D 打印问题，只需要证明一件事——

> 当用户带着一个模糊的抱怨和一个错误的假设来时，系统能先把问题拆对，再去找证据，最后给出有引用、有边界、有下一步的答案。

这件事刚好是「提出问题比解决问题更重要」的可执行版本。

## 2. 评分拆解：90 分是主战场

评分 100 分，其中 90 分是作品质量，10 分是传播热度。

| 维度 | 权重 | 评委真正在看什么 | 我们拿什么回应 | 目标 |
|---|---:|---|---|---:|
| 场景价值 | 25 | 是不是真问题、有没有人用、是否比现有方案更好 | 3D 打印新手的高频痛点；旧项目获奖经历；4 个贴近真实语气的合成案例 | 20–22 |
| 实践完成度 | 25 | 是否真的跑起来、是否真的调用、有没有工程细节 | 可运行 Web 原型；live/replay 双模式；14 次真实调用/40 条证据；trace 带 RequestId | 20–22 |
| 结果质量与验证 | 20 | 结果是否可信、是否验证、边界是否清楚 | 四案例 live 表；18 条数值断言；2 处冲突；17 个有引用步骤；单次运行与合成私域明示 | 15–17 |
| 创意与创新性 | 10 | 有没有一个记得住的点子 | 「提问编译器」：缺口类型、反向证据、冲突卡、证据不足追问 | 7–8 |
| 表达与可读性 | 10 | 是否好读、结构是否清楚、图文是否配合 | 5000 字长文；4 张正文截图 + 7 张备用；先结论后论证；代码块克制 | 8–9 |
| 传播热度 | 10 | 阅读/点赞/收藏 | 不刷量；靠标题、封面、评论区答疑拿及格分 | 5–7 |

**现实判断**：热度 10 分拿满需要「100 赞 + 1 万阅读 + 50 收藏」量级，单人新号很难。把精力放在 90 分里拿 75–80，比追热度更划算。

传播分的换算（按赛事规则）：`点赞/10 + 阅读/1000 + 收藏/10×2`，原始分 30 封顶，再折算到 10 分。也就是说：

- 30 赞 + 1500 阅读 + 15 收藏 ≈ 7.5 原始分 ≈ 2.5/10；
- 100 赞 + 10000 阅读 + 50 收藏 = 30 原始分 = 10/10。

所以热度策略是「及格即可」，不做互赞、不买量、不标题党。

## 3. 差异化：和「接入实录」类文章不一样

目前同赛道已有一篇偏「接入踩坑」的文章（端侧 RAG + SearchPro，讲鉴权、签名、参数）。这类文章的价值是工程参考，但评委看完记不住「它解决了谁的什么问题」。

我们的差异点：

| 维度 | 常见接入文 | 本文 |
|---|---|---|
| 用户 | 「某部门知识库」 | 一个具体的 3D 打印新手，带着错误假设 |
| 核心动作 | 把 SearchPro 接进 RAG | 先编译问题，再决定搜什么 |
| 检索 | 一条 query 打天下 | 2–4 条有目的、有覆盖关系的任务书 |
| 反证 | 很少 | 专门为「是不是机器坏了/要不要回滚」生成 rule_out 查询 |
| 冲突 | 尽量回避 | A1 的 60℃ vs 50℃、P1S 的 65℃ vs 50℃/40℃，单独列「需要你知道的分歧」 |
| 验证 | 主观感受 | 四案例 live 表：调用/证据/断言/冲突/覆盖/引用 |
| 边界 | 容易写成「效果很好」 | 明示「单次 live 运行 + 合成私域笔记」，不冒充线上准确率 |

一句话：**别人证明「能查到」，我们证明「知道该查什么、什么时候不该下结论」。**

### 5.2 配置（二选一）

```powershell
# 在仓库根目录
Copy-Item .env.example .env
notepad .env
```

路径 A（推荐，简单）：

```dotenv

```

路径 B（腾讯云 TC3）：

```dotenv
WSA_SECRET_ID=你的SecretId
WSA_SECRET_KEY=你的SecretKey
WSA_MODE=live
```

### 5.3 验证

```powershell
python live_check.py             # 先打一条真实请求，确认 key/网络/额度
python smoke.py                  # 编译器：槽位/缺口/查询
python bench.py --live --json runs/bench-live.json
python server.py --mode live --port 8765
```

`bench.py --live` 的验收线：

- 四案例 `failed=False`；
- 每条 call 的 `request_id` 不是 `replay-*`；
- 至少 3 个案例有官方来源；
- 至少 1 处冲突被展示（A1 或 P1S）；
- 没有 `ReplayMiss` / `UnauthorizedOperation` / `RequestLimitExceeded`。

## 10. 三条不做

1. **不把 replay 写成 live**。评委只要看到 `replay-*` 的 RequestId，整篇的可信度就没了。
2. **不把合成页面当真实来源引用**。文章里可以演示，但必须标注；live 后换成真实 URL。
3. **不追热点堆功能**。13 天只够把一个场景打穿；加三个赛道不如把一个案例讲透。
