# 凭证配置：你到底该拿哪个 key

先对齐一个事实：`AKI...` 开头的是**腾讯云 SecretId**，`sk-...` 开头的才是**元宝搜索服务 API KEY**。两者不是一回事，不能混填。

你现在遇到的是：

```text
FAILED: UnauthorizedOperation / 未授权操作。
HTTP 200 · see runs/live_check.json
```

因为 `WSA_API_KEY` 里填的是 `AKI...` SecretId，Bearer 路径把它当成 `sk-` 服务密钥，服务端只能回“未授权”。

下面二选一，**推荐 A**。

---

## A. 服务 API KEY（推荐，最简单）

适合：只想让 demo 跑起来，不想处理签名。

1. 先确认服务已开通：打开 [元宝搜索控制台](https://console.cloud.tencent.com/wsapi/index)，在「概览」页点「开通服务」，按页面完成开通/购买。赛事邀请码的 6000 次额度也在这里领取或兑换。
2. 开通后，仍在「概览」页，找到「服务 API KEY 方式」，点「创建 API KEY」。
3. 输入名称（例如 `deshifu-demo`），确定。
4. 弹窗里会出现 `sk-` 开头的明文 key。**它只显示一次**，点「复制」或「下载 CSV」保存。
5. 打开项目根目录的 `.env`，改成：

   ```dotenv
   WSA_API_KEY=sk-你的key
   WSA_SECRET_ID=
   WSA_SECRET_KEY=
   WSA_MODE=auto
   ```

   注意：`WSA_API_KEY` 这一行不要留 `AKI...`；`WSA_SECRET_ID` / `WSA_SECRET_KEY` 要清空，避免 auto 选错路径。

6. 验证：

   ```powershell
   python live_check.py
   ```

   成功时会打印 `OK`、`RequestId`、`version`、`latency_ms` 和前三条结果，并把完整响应写到 `runs/live_check.json`。

官方步骤（带截图）：[服务 API KEY 方式](https://cloud.tencent.com/document/product/1806/130615)

---

## B. 腾讯云 TC3（SecretId + SecretKey）

适合：你已经有一对 SecretId/SecretKey，或者团队要求走云 API 签名。

1. 同样先确认服务已开通：[元宝搜索控制台](https://console.cloud.tencent.com/wsapi/index) → 开通服务。
2. 打开 [API 密钥管理](https://console.cloud.tencent.com/cam/capi)。
3. 点「新建密钥」，弹窗会同时给出：
   - `SecretId`：`AKI...` 开头
   - `SecretKey`：只在创建时显示一次，必须当场保存
4. 如果你现在只有 `AKI...` 的 SecretId、没有配对的 SecretKey，**不能**用 TC3；请重新新建一对，或直接走 A。
5. `.env` 改成：

   ```dotenv
   WSA_API_KEY=
   WSA_SECRET_ID=AKI你的SecretId
   WSA_SECRET_KEY=你的SecretKey
   WSA_MODE=auto
   ```

   注意：`WSA_API_KEY` 必须留空，否则代码会优先走 Bearer。

6. 验证：

   ```powershell
   python live_check.py
   ```

官方步骤（带截图）：[腾讯云标准方式](https://cloud.tencent.com/document/product/1806/121802)

## 仍然报错时怎么排查

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| `UnauthorizedOperation`，HTTP 200 | 把 SecretId 当成了服务 key；或服务未开通；或子账号没有 WSA 权限 | 看本文开头；确认 `sk-`；确认控制台已开通；子账号给 WSA 全读写 |
| `AuthFailure.InvalidSecretId` | key 类型不对，或复制时多了空格/换行 | 重新复制；确认是 `sk-` 或配对 SecretId |
| `AuthFailure.SignatureFailure` | TC3 签名计算错误 | 确认 SecretKey 正确；确认系统时间准确；用 `live_check.py` 复现 |
| `RequestLimitExceeded` | 超过 QPS/配额 | 降低并发；确认 6000 次/月额度已到账 |
| `InvalidParameter` | `Cnt` 不是 10/20/30/40/50，或 `Freshness` 格式不对 | 看 `runs/live_check.json` 里的 `params` |

不要把 `.env`、完整 key、带 key 的截图提交到仓库或文章。项目已把 `.env` 写进 `.gitignore`。

---

## 一句话判断

- 控制台里点「创建 API KEY」拿到的、以 `sk-` 开头的 → 填 `WSA_API_KEY`。
- 控制台「API 密钥管理」里成对出现的 `AKI...` + SecretKey → 分别填 `WSA_SECRET_ID` / `WSA_SECRET_KEY`，且 `WSA_API_KEY` 留空。
- 只有 `AKI...` 一个字符串 → 它不是服务 key，单独用不了。
